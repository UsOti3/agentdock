## 本轮修正的实际问题

- 原“连接测试”仅证明桥接进程存在，改为真实初始化 AgentDock 后才显示成功。
- 不读取现有受保护服务凭据。改用 AgentDock 官方 stdio 方式，在独立状态目录运行；原 HTTP 服务认证并未被关闭或绕过。
- 找到 DSH NEXT 包内 CLI；为命令行生成独立的依赖路径适配副本，复用已有 VPS 模型路线，不改桌面 Bot。
- 原取消逻辑过早写成“已取消”，现在等待子进程关闭；取消失败保持占用，不自动开始第二个任务。超时实测会终止本次子进程树。
- 补齐 Windows 特殊设备名、尾随点/空格、硬链接、目录替换检查。搜索先建立允许访问的文件列表，再让 AgentDock 读取正文。
- 配对令牌存储限定到扩展可信上下文；扩展按钮拒绝网页脚本伪造点击。只检查最新回复，避免从旧对话重新执行历史请求。
- 审计写入在操作之前；审计失败时拒绝执行。子进程不继承桥接、云端或模型密钥环境变量；HTTP 客户端禁止重定向。

## 仍然存在的边界

目录校验与人工点击不等于操作系统沙箱。DSH/AgentDock 以当前账号运行；本轮没有完成多账户隔离、真实资料自动脱敏、所有网络出口检查或恶意网页攻防测试。浏览器扩展的 closed Shadow DOM 不是可信 UI 的绝对安全边界，仍需防范诱导点击、网页布局遮挡和提示词注入。

多步任务运行状态在内存中，桥接崩溃后不会恢复旧任务。模型网络存在超时可能；不能自动重放状态未知的写入任务。
